# Master Roadmap

| Phase | Scope | Exit condition |
|---|---|---|
| 0 Re-foundation | Reconciliation, inventories, taxonomy, architecture, roadmap | Normative baseline approved |
| 0A Agent prompt governance | Historical audit, layered template, review gates and design waves | Governance documented; Wave 1 authorized separately |
| 0B Wave 1 coordinator prompts | Nexus, Stasis, Rector and Gerendi documentary prompts and evaluations | Four prompts pass P0-P14; none configured or available |
| 0C Wave 2 governance prompts | Governance, security, privacy, risk, Founder controls and portability | Eighteen prompts pass P0-P14; none configured or available |
| 1 Clean technical baseline | Clean Development project, migration `00001`, environments, secrets, minimum RLS/observability | Local and Development gates pass |
| 2 Platform Core | Identity, profiles, roles, permissions, audit, API, Data Router contracts, Agent Registry | Core contracts operational |
| 3 Product shell | Flutter shell, Stasis home, navigation, placeholders, profile, settings, auth | Product shell verified |
| 4 Development Surface | Rector, technical chat, tasks, docs, gates, authorizations, executions | Controlled Development workflow |
| 5 Administration Surface | Gerendi, users, roles, billing, support, growth, analytics | Authorized admin workflow |
| 6 Stasis intelligence | Orchestration, selection, memory, research, traceability | Governed intelligence loop |
| 7 Product areas | Salud, Nutricion, Entrenamiento, Wellness in waves | Area-specific acceptance gates |
| 8 Business and scale | Payments, success, moderation, regions, sharding, staging, production, stores | Scale/readiness decisions |

Phases are sequential gates, not automatic execution authorizations. Product
areas are delivered in waves. The next package must be selected after Founder
review; parallel initiation is not approved.

Wave 2 documentary migration is complete. The next recommended agent package is
`STASISLY-AGENTS-004`, limited to Wave 3 Architecture, Data and Multi-Agent
Platform prompts. It does not include runtime configuration or activation.

Development Surface's approved purpose is to build and evolve Stasisly through
a conversational, visual, governed, traceable and auditable interface. Its
delivery loop uses the minimum sufficient team, isolation, tests, correction,
evidence, approval, Git and authorized deployment. The surface itself remains
not implemented.
